# MA FP-aware：三个场景独立诊断

上传整个ma_fpaware_3scene目录到平台toma下，与test平级。
父目录channel_model.py、system_model.py、algorithms.py、inner_solver.py、outer_solver.py均不用替换。
新方法仅在本目录ma_fp_aware.py实现：运行时临时替换MA位置sweep，原算法文件不改。

固定权重0.001，三个场景8001、8005、8010，每项一个独立初态、只运行一次。
从上传的33738原实验中直接携带这三项的完整初态、配置和原MA终态；新旧方法使用相同实际坐标和初始资源。
不从原MA终态起步，不使用跨权重热启动，不重新运行原MA。
内层上限1500，外层2000，绝对停止容差1e-4，候选位置FP最多2轮。
候选点先检查原MA的区域和最小间距约束，再做2步FP，用真实联合目标进行Armijo验收。
接受时同步复制候选资源；拒绝的候选不能写回当前位置或资源。
原MA的两条方向搜索和阵元顺序保留；更新梯度仍固定当前资源。

提交：
    cd /home/lyq00008339/Lihuang_Li/toma/ma_fpaware_3scene
    sbatch submit_three.sh

只申请3核、3进程，数值库单线程，同时跑三项任务；申请56核也不会让这三项单线程任务更快。
默认8GB、12小时申请上限，不是完成时间承诺。使用原cpu分区、JM_CVX环境。
每25轮输出进度；到预算上限保存converged=false，不自动续算。
已有完整记录重复提交时只校验复用，不继续优化；想重跑须使用新的HPC_OUTPUT目录。

输出在results/three_作业ID：
- comparison.csv：新旧目标值、耗时、外层轮数、收敛标记与候选FP调用数。
- scene_*/initial.npz、final.npz、record.json、diagnostics.json：完整状态和每轮位置更新诊断。
- all_data.json：三个场景的统一数值汇总。
- 同级three_作业ID_bundle.zip：结果、日志及实际使用的源码配置快照。
原方法的时间来自之前56进程作业，新作业只有3进程；耗时比较可能受节点与负载影响，不能直接解释为纯算法加速比。

本地验证：3进程、每场景2轮外层/内层的短程运行；全部通过几何、功率、目标非下降、状态一致性和打包检查。
另用拒绝候选测试验证未接受资源不会污染当前状态。
短程运行的目标均高于原MA已保存目标，但三项都尚未收敛，不作为最终收敛速度证据。
