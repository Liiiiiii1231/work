# 相邻权重点筛选测试

场景8001，原run_33360保存的18点逐场景表。最新run_33570的20点原ZIP当前无法从原路径读取，因此没有声称本次是20点版本，也没有插值或伪造新点。

## 规则

每个目标权重仅比较原始表中的自身和直接左右邻点，端点只有一个邻点。候选需通信总速率C>=原C且感知总速率S>=原S，再按目标权重F=w*C/10+(1-w)*S/5取最大；同分保留原解。候选池在开始前冻结，非顺序递推。四方案独立筛选，不跨方案或场景取点。

同一状态的速率不由评价权重改变；在共享配置/可行域的协议下，重新加权已存速率等价于直接评价原状态的目标。本次没有读取全部NPZ并重新核验可行性，结论限于已保存表的规则测试；不是用候选状态重新启动求解器。

## 结果

|方案|被替换点数|存在WSR更高邻点但被双速率限制排除的点数|
|---|---:|---:|
|proposed|6/18|8|
|b6|11/18|4|
|b2|0/18|12|
|b3|11/18|4|

全部72个输出点的C、S、目标WSR均不低于各自原点。此规则是局部Pareto支配筛选，比只要求WSR提高更严格；WSR更高但牺牲其中一项速率的候选会被排除，不能据此保证曲线平滑、单调或形成完整Pareto前沿。重复选中同一邻点时图上会重合，但CSV保留所有目标权重点。

之前纯感知候选虽然在w=0.2下WSR更高，但会降低通信总速率，因此按用户本次规则通常无法入选。这不是筛选器没有检查它，而是规则要求两项都不降低；本例还限制只考虑直接邻点。
