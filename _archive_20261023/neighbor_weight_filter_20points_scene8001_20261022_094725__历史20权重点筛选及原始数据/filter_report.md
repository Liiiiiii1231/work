# 最新20点相邻筛选：场景8001

## 本次执行

输入为用户新上传的tradeoff_per_scene.csv，8000条、100场景、20权重、4方案。本次仅筛选场景8001的80个点，没有对100场景取平均，也没有运行优化或修改正式代码。输入完整副本保存在本目录，避免原下载路径失效。

## 确定规则

每个方案独立操作：对于当前权重，从原始表的左邻点、自身、右邻点取候选，端点只有一个邻点。候选通信总速率和感知总速率都必须大于等于当前原值，按当前目标F=w*C/10+(1-w)*S/5取最大；相同目标优先原解。候选池冻结，不递推使用已替换点。比较为严格的非降低，不用容差接受任何速率下降。

全部80点逐点核验通信、感知、WSR均不低于对应原点。重复选择相同原始候选时，图上点可能重合，但selected_points.csv保留所有目标权重。

这种规则是相邻候选中的支配改进，不等于允许所有通信感知交换的WSR优化。因此它可能排除目标更高、但某一项速率较低的解；不能保证回折全部消失或曲线向外鼓。纯感知状态通常降低通信速率，因此无法因高WSR就入选。

本次用已有速率重新加权评价候选；没有加载所有NPZ重新核验几何约束。结论以同场景各权重采用相同模型和可行域为前提，与此前核实的运行协议一致。若要候选状态在目标权重下先重新优化再比较，则需另做计算实验。
